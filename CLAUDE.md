# Strauss Car Advisor

Hackathon app: Hebrew chatbot that compares monthly NET pay for company-car alternatives.

## Role

Senior software engineer specializing in payroll calculations and LLM agents. Precise and conservative: prefer "unknown" over guessing; never change an expected test value to make a test pass.

## Golden rules

- All money math lives in server/bl/engine (pure TypeScript, server only). The LLM never computes or invents numbers.
- Source of truth for formulas, data and expected results: docs/SPEC.md (sections 3, 4, 8). If code and SPEC disagree, STOP and ask me.
- No money constants in code: read them from server/data/strauss-rules.json.
- UI is Hebrew, RTL. Code, comments and commit messages are in English.
- Never commit secrets (.env\*). Never log salary data.
- 3-tier: the client (src/) talks only to the API (src/api/client.ts) and imports only src/ and shared/. Engine, agent and storage run on the server. tests/architecture.test.ts enforces this.
- Every engine function has a vitest test. Run `npx vitest run` and `npm run build` before saying a step is done.
- Never change an expected value in a test to make it pass; fix the code.
- Work in small steps. After each step, summarize in 3 lines what changed and how I can verify it.

## Structure

3-tier layout (2026-10-17):

- `shared/types.ts`: types used by client and server (domain, chat, tickets, API shapes). Types only.
- `server/index.ts`: entry (config → DAL → BL → API, then Vite in dev or `dist/` in production). `server/config.ts`: the only reader of server env vars; refuses to start in production without GEMINI_API_KEY, SUPABASE_URL, SUPABASE_SERVICE_ROLE_KEY (login).
- Auth (branch feat/auth): Supabase Auth email + password, tokens only in httpOnly cookies (`server/api/authCookies.ts`), role in `app_users`. `requireRole` in `app.ts`: /sessions, /payslip, /meta any user; /tickets rep+admin; /admin admin; /tickets/summary, /health, /auth public. Each session has `userId`; someone else's session is 404. Client screens per role: `SCREENS_BY_ROLE` in `src/ui/Header.tsx`. Without Supabase (dev) login is off and everything is open.
- `server/api/`: API layer. `app.ts` (routing), `middleware.ts` (security headers, CORS, rate limits, Bearer tokens, errors), `validate.ts` (every body/param), `routes/` sessions, tickets, admin, payslip.
- `server/bl/`: business logic. `engine/` (pure; `types.ts` re-exports shared), `agent/` (loop, tools, guard, llm with an injected transport), `llm/gemini.ts` (model list, cooldown, time budget), `services/` session, ticket, admin, repAnswer, taxCsv.
- `server/dal/`: `Repository` interface; `supabaseRepository.ts` (REST, service role key), `fileRepository.ts` (JSON in DATA_DIR, dev / single instance).
- `server/data/`: strauss-rules.json, catalog.json, occupations.json, employees.json, tax-seed.json, aliases.
- `src/`: client only. `api/client.ts` (all calls; session id in localStorage; on 401 renews via GET /api/auth/me and retries once, then shows login), `ui/` (Tailwind) incl. `AccessGate.tsx` (login form).
- `tests/*.test.ts`, `tests/*.check.ts`, `supabase/schema.sql` (RLS on, no anon access), `Dockerfile`, `data/raw/` (rules, catalog.xlsx, vehicles.csv)
- Branches: `main`, `agent`, `styling`, `refactor/3-tier`. Commit format: `type(branch-name): summary`, body with `### What`, `### Why`, `### How`.
- Plan and status: `docs/AUDIT.md`, `docs/TODO.md`, `guide-current.html`

## Known pitfalls

- `server/index.ts` uses `dotenv.config()`, which reads only `.env` (not `.env.local`). `npm run dev` does not reload server code or `.env`: restart it after changing either.
- `.env.example` must contain variable names only. Old real keys are still in git history (commits cd7cace, 869fb74). Never open or print `.env`; change single lines with sed if asked.
- `GEMINI_MODEL` is a comma-separated, ordered model list; `generateWithFallback` in `server/bl/llm/gemini.ts` falls back on 429/503/404/timeout (`GEMINI_MODEL_TIMEOUT_MS`). Check real model names at https://generativelanguage.googleapis.com/v1beta/models before using one (`gemini-2.5-*`, `gemini-pro` return 404; there is no `gemini-3.8-flash-lite`).
- Tool calls must go to Gemini as functionCall/functionResponse with the raw model content (thought signatures) passed back unchanged. Plain-text tool results make weak models print "[קריאה לכלי …]". Fixed in `b30f4a0`.
- A full agent turn with flash-lite takes about 26s; the turn limit in `loop.ts` is 30s.
- Supabase is reached only by the server with SUPABASE_SERVICE_ROLE_KEY; anon has no grants (schema.sql). The old `VITE_SUPABASE_*` / `VITE_FALLBACK_*` vars are unused; the server warns when they are set.
- `buildScenario` has no real `keep` branch: it picks the first car of the group.
- `findCarByIdOrName('COROLLA CROSS')` returns COROLLA (includes-match before exact match).
- `server/bl/services/taxCsv.ts` picks columns by term priority with exact headers first (`findColumn`); the drive column "1-חשמלי.2-היברידי.3-פלג-אין" is coded 0/1/2/3 like the catalog. Verified on data/raw/vehicles.csv: 20/20 catalog cars match on benefit and drive code (2026-10-17).
- The engine uses catalog benefit values; the uploaded Tax Authority records (DAL `tax_records`) are used only by the admin lookup, not by calculations.
- `guard.ts` checks only numbers with ₪/% or >= 10; allowed = this turn's tool outputs, non-bot messages and profile values. `update_profile` runs every number through `server/bl/agent/normalize.ts` first. The group letter is saved only when the employee wrote it as a word of its own (`groupStated`).
- Each browser has its own conversation (session id in localStorage). The file store is single-instance; rate limits and per-session locks are in memory per instance.
- The agent debug trace prints to the server console (development only, numbers >= 100 masked).
- EV gross-up is rounded to whole shekels (net +250.05 / +249.89). This is an open SPEC question; ask before changing it.
