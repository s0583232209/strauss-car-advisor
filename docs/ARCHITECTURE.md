# ארכיטקטורה: יועץ הרכב של שטראוס

צ׳אטבוט בעברית שמשווה את הנטו החודשי בין חלופות רכב חברה. שירות Node.js אחד בשלוש שכבות. הדפדפן מדבר רק עם `/api`, ואין לו גישה לבסיס הנתונים, למודל או לסודות.

## איפה המודל

Gemini נקרא רק מהשרת, דרך [`server/bl/llm/gemini.ts`](../server/bl/llm/gemini.ts): רשימת מודלים לפי סדר, מעבר אוטומטי למודל הבא כשמודל לא עונה, ומגבלת זמן לכל תור של הסוכן.

- **המודל לא מחשב מספרים.** הוא מבין את העובד, אוסף נתונים, קורא לכלי המנוע ומסביר את התוצאה.
- **שומר מספרים:** כל מספר בתשובה חייב להגיע מהכלים, מהעובד או מהפרופיל. אחרת התשובה נחסמת.
- **טיוטות של יתרונות וחסרונות** לכל רכב, בלי מספרים. מנהל מאשר אותן לפני שהעובדים רואים אותן.
- **סוכן מעבר לכסף:** מומחה רכב שעונה על התאמת הרכב לחיים של העובד (ראו בהמשך).

## סוכן מעבר לכסף

הנטו הוא רק חצי מההחלטה. בכרטיס ההשוואה יש צ׳אט נפרד עם סוכן רכב מומחה. העובד מספר על השגרה שלו (ילדים, נסיעות, חניה, טעינה) ושואל איזה רכב מתאים לו, מה הטווח בפועל או מה נוח יותר בעיר. הסוכן ממליץ על רכבים מהרשימה שהעובד רשאי לבחור, עם נימוק מקצועי ודגשים לנסיעת מבחן.

- **פרטיות:** למודל נשלחים רק תפקיד, קבוצת זכאות, מספר ילדים, הרכב הנוכחי ושכר הבסיס מעוגל כלפי מטה לאלפים. לא נשלחים שם, עמלות, בונוס, ניכויים, נקודות זיכוי, השתתפות, שווי שימוש או מחירי רכבים. הפרופיל נקרא מהשיחה השמורה בשרת, לא מהדפדפן.
- **כלים:** `list_my_cars` (הרכבים שהעובד רשאי לבחור) ו-`get_car_details` (זהות הרכב, סוג הנעה, קבוצה ויתרונות וחסרונות מאושרים). אף כלי לא מחזיר סכום כסף.
- **שומר:** תשובה עם סכום כסף או עם השכר (גם מעוגל) חוזרת למודל לניסוח מחדש. נתונים טכניים (טווח, כוח סוס, תאוצה, תא מטען) מותרים, כהערכה לפי נתוני היצרן ועם הסתייגות לגבי השימוש בפועל.
- **בלי כסף:** על שאלה כספית הסוכן מפנה לכרטיס ההשוואה, שמחושב רק במנוע השכר.

```mermaid
sequenceDiagram
  autonumber
  participant U as עובד (דפדפן)
  participant A as API
  participant C as סוכן מעבר לכסף
  participant G as Gemini

  U->>A: POST /api/sessions/:id/car-fit (שאלה + השיחה הקודמת)
  A->>A: התחברות, בעלות על השיחה, קלט, הגבלת קצב
  A->>C: הפרופיל והרכבים מההשוואה השמורה
  C->>C: פרופיל מצומצם, שכר מעוגל לאלפים
  C->>G: השאלה + פרופיל מצומצם + רשימת הרכבים + כלים
  G-->>C: קריאה לכלי list_my_cars
  C-->>G: רכבים בלי מחירים
  G-->>C: המלצה בעברית
  C->>C: בדיקה: בלי סכומי כסף ובלי השכר
  C-->>U: תשובת הסוכן
```

## איפה הנתונים

- **Supabase** (Postgres והתחברות עם אימייל וסיסמה), לפי [`supabase/schema.sql`](../supabase/schema.sql):
  - `sessions`, `messages`: שיחות.
  - `tickets`: פניות לנציג.
  - `app_users`: תפקידים.
  - `app_settings`: כללים, קטלוג ויתרונות וחסרונות שהמנהל מעלה.
  - `tax_records`: שווי שימוש מקובץ רשות המסים.
- RLS פעיל ואין גישה אנונימית. רק השרת ניגש לנתונים, עם service role key.
- **ערכי ברירת מחדל:** [`server/data/`](../server/data). המנהל מחליף אותם בהעלאת קובץ.

## מסלול של שאלה אחת

"כמה נטו ארוויח אם אעבור ל-MG4?": מהצ׳אט ועד כרטיס ההשוואה.

```mermaid
sequenceDiagram
  autonumber
  participant U as עובד (דפדפן)
  participant A as API
  participant S as שירות השיחות
  participant G as Gemini
  participant E as מנוע שכר
  participant D as Supabase

  U->>A: POST /api/sessions/:id/messages
  A->>A: התחברות, תפקיד, בעלות, קלט, הגבלת קצב
  A->>S: תור של הסוכן
  S->>G: ההודעה + הפרופיל + הכלים
  G-->>S: קריאה לכלי run_comparison
  S->>E: חישוב הנטו לפי הכללים
  E-->>S: תוצאת ההשוואה
  S->>G: תוצאת הכלי
  G-->>S: הסבר בעברית
  S->>S: שומר המספרים בודק את התשובה
  S->>D: שמירת השיחה וההשוואה
  S-->>U: הודעה + כרטיס השוואה
```

## מה רץ איפה

| איפה | מה |
|---|---|
| דפדפן | ממשק React בלבד |
| שרת Node (Docker, או Vercel: קבצים סטטיים ופונקציה אחת עבור `/api`) | API, לוגיקה עסקית, מנוע, שני הסוכנים, גישה לנתונים |
| Google | מודלי Gemini |
| Supabase | נתונים, משתמשים והתחברות |

## איך שומרים על ההפרדה

המבחן [`tests/architecture.test.ts`](../tests/architecture.test.ts) בודק בכל הרצה:

- הלקוח מייבא רק את `src/` ואת `shared/`.
- ה-API מגיע ללוגיקה העסקית רק דרך השירותים, ואף פעם לא לשכבת הנתונים.
- רק [`server/config.ts`](../server/config.ts) קורא משתני סביבה.
- אין בלקוח סכומים או שיעורים שכתובים בקוד.
